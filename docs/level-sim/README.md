# Симуляция прогона уровня на двоих (без игры)

Настоящий `LevelRun` и настоящий файл `sandy_meadow.json` на подставном `RunHost` (`Sim.java`): позиции, флаги проверок и журнал вызовов задаёт тест. Игра не запускается, обычная JVM, прогон занимает секунды.

```
cd docs/level-sim
./gradlew simulate --no-daemon -Dorg.gradle.jvmargs=-Xmx900m > run.log 2>&1
grep -E "(STDOUT|STDERR)\]: (S[0-9]|  ok|  FAIL|ИТОГ|      )|Exception" run.log
# другой файл уровня: -PlevelFile=/путь/к/level.json
```

- Перед запуском собрать моды и положить jar в `~/.minecraft/mods` (проект берёт их оттуда).
- Свежую сборку, не копируя её в игру: положить все шесть jar в свою папку и добавить `-PmodsDir=/папка/`.
- Сценарии (S1–S19; S17 общий чекпоинт ждёт всех, S18 ожидание у чекпоинта и `checkpoint_resumed`, S19 несколько областей миссии; S13 миграция триггеров в миссии, S14 область видимости событий миссии, S15 ячейки отката, `on_enter` и события чекпоинтов на правленом JSON уровня):
  S1–S10: сбор и старт на двоих, утренняя миссия, гибель одного до и во время полёта (взаимный сброс `k_jungle`⇄`y_jungle`), закончил раньше и стоит (hold), выход из сети и возвращение, пещера и чекпоинты, прохождение до конца, `abandon`, уход участника, гибель обоих разом.
- Локации в тесте — квадраты (`Sim.store()`), персонажи и предметы мода заменяются ванильными (реестры мода без игры не заполнить; логике прогона имена безразличны).
- **Не проверяет:** настоящий сервер (`LevelManager`, телепорты, возрождение), механики шара и лавы, геометрию мира, кат-сцены, интерфейс.

## Установка с GitHub (`./gradlew gitTest`)

Проверка `GitRelease` и `GitSession` SmesharikiMod на локальном HTTP-сервере, изображающем GitHub (`sim/GitTest.java`): нормальная установка jar и мира, замена
старого файла (`.smesharikimod-old`), неверная сумма, zip-slip, переадресация на чужой узел, неверное имя репозитория, http не на localhost. Нужен свежий `smesharikimod-1.0.0.jar` в `~/.minecraft/mods`.

`./gradlew realGit` ставит последний релиз `NoPasaRun/smeshariki-demo` с настоящего GitHub в пустую временную папку (сумма, мир, повторная проверка).

В `gitTest` (2026-11-21) — обновление установленного мира по файлам (`WorldUpdate`): правка игрока в нетронутом релизом файле остаётся, изменённое релизом ставится с резервной копией, без памяти о прошлой установке — по отличиям, рабочий мир автора (своя история версий) — раздел «Мир» выключен, релиз без `contents` мир не трогает, путь с `..` отвергается.
