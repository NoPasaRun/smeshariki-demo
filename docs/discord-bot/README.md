# Бот сервера Discord

Роли через GitHub, заявки на роли, команды `/версия` и `/установка`, мониторинг сервера в Telegram.

Кнопка в канале `#добро-пожаловать`: участник вводит ник GitHub, бот выдаёт код и просит вписать его в поле **Bio** профиля GitHub (так видно, что аккаунт его). Когда код найден, бот смотрит публичные репозитории и, если среди собственных (не форков) есть проект на Java, выдаёт роль «Разработчик». Остальные роли выдаются вручную (вторая кнопка отправляет к админу).

**Где работает (2026-11-15):** сервер `hetzner_gearstore` (ssh-алиас), служба `smeshariki-role-bot`, файлы в `/opt/smeshariki-role-bot`, токен в `/etc/smeshariki-role-bot.env` (600). Журнал: `ssh hetzner_gearstore journalctl -u smeshariki-role-bot -f`. Обновить код: скопировать `bot.py` в `/opt/smeshariki-role-bot/` и `systemctl restart smeshariki-role-bot`. На сервере диск заполнен на 94%, бот занимает около 38 МБ.

## Запуск на сервере (Linux, systemd)

```bash
sudo useradd -r -m smeshariki
sudo mkdir -p /opt/smeshariki-role-bot && sudo cp bot.py requirements.txt /opt/smeshariki-role-bot/
cd /opt/smeshariki-role-bot && sudo python3 -m venv venv && sudo venv/bin/pip install -r requirements.txt
sudo chown -R smeshariki: /opt/smeshariki-role-bot

# токен — только в этом файле, права 600
sudo install -m 600 /dev/null /etc/smeshariki-role-bot.env
echo 'DISCORD_BOT_TOKEN=...токен бота...' | sudo tee -a /etc/smeshariki-role-bot.env >/dev/null
# по желанию, чтобы GitHub не ограничивал запросы: GITHUB_TOKEN=... (достаточно токена без прав)

sudo cp smeshariki-role-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now smeshariki-role-bot
journalctl -u smeshariki-role-bot -f     # в логе должно появиться «Бот запущен»
```

Когда бот запущен, один раз опубликуйте сообщение с кнопками (с любой машины, где задан `DISCORD_BOT_TOKEN`):

```bash
python3 bot.py post
```

Повторный `post` создаст второе сообщение: старое удалите. Кнопки работают постоянно и после перезапуска бота, пока жив процесс `run`.

Проверка без Discord: `python3 bot.py check <ник GitHub>`.

## Что нужно от сервера Discord

- Роль бота `ManagerBot` стоит выше «Разработчика» (сейчас так и есть), иначе выдача роли не сработает.
- Привилегированные намерения (Gateway Intents) не нужны.
- Идентификаторы сервера, канала и роли заданы в начале `bot.py`; можно переопределить переменными `GUILD_ID`, `WELCOME_CHANNEL_ID`, `DEVELOPER_ROLE_ID`.

## Как устроена проверка

Код для Bio (`smeshariki-<10 символов>`) считается как HMAC от ID участника в Discord и ника GitHub с секретом из токена бота: хранить его не нужно, пережить перезапуск он может, а подделать код для чужого ID нельзя. Ник и Bio бот читает через публичный API GitHub (ответ кэшируется около минуты, поэтому после правки Bio нужно подождать). Без `GITHUB_TOKEN` лимит GitHub — 60 запросов в час с адреса сервера (на проверку идёт два запроса).

Ограничение: роль «Разработчик» выдаётся автоматически, как только код найден и есть Java-проект. Критерий «есть Java-проект» формален (чужой, но настоящий аккаунт тоже подойдёт). Каждая выдача пишется в журнал (`роль выдана: discord=… github=… java=…`), роль можно снять вручную.

## Заявки на роли и команды (2026-11-15)

- Кнопка «GitHub нет / другая роль» открывает выбор: «Игрок» выдаётся сразу, «Строитель», «Сценарист», «Постановщик», «Тестировщик», «Дизайнер» уходят заявкой в закрытый канал `#заявки-на-роли`. Админ или модератор решает кнопками «Одобрить» / «Отклонить» (кнопки зашиты в `custom_id`, переживают перезапуск; участнику приходит личное сообщение, если оно открыто).
- Через GitHub теперь выдаются две роли: «Разработчик» (свой Java-проект, не форк) и «Контрибьютор» (коммиты в репозиториях владельца `RELEASES_REPO`; поиск коммитов `author:<ник> user:<владелец>`).
- Команды: `/версия` (последний релиз демо, кэш минута) и `/установка` (краткая инструкция).
- `python3 bot.py edit <id сообщения>` меняет текст опубликованного сообщения, не создавая второго.
- AutoMod (правила на сервере, не в коде): русский мат, спам, массовые упоминания, приглашения на другие серверы; админы и модераторы исключены, нарушения пишутся в `#логи-модерации`.

## Мониторинг в Telegram

`monitoring/watch.sh` + `smeshariki-watch.timer` (каждые 5 минут): пишет в Telegram, когда бот ролей упал или сам перезапускался, и когда диск заполнен на 90% и больше (и когда пришёл в норму). Ключи — в `/etc/smeshariki-alert.env` (права 600): `TG_TOKEN=…` (бот от @BotFather) и `TG_CHAT_ID=…`. Без ключей скрипт ничего не делает. Для сервера: файлы в `/opt/smeshariki-role-bot/watch.sh` и `/etc/systemd/system/`, `systemctl enable --now smeshariki-watch.timer`. Журнал systemd на сервере ограничен 200 МБ (`/etc/systemd/journald.conf.d/size.conf`).

## Голосовые каналы совместной игры

Вход в голосовой канал «➕ Создать совместную игру» создаёт новый канал `совместная-игра-N` (наименьший свободный номер от 2, 2 места, создателю дано право управлять каналом) и переносит туда. Пустой временный канал удаляется через 2 секунды; после перезапуска бот удаляет пустые временные каналы. Сам `совместная-игра` постоянный. Ограничения: не чаще раза в 30 с на обычного участника (у админов, модераторов, владельца и всех с правом «Администратор» кулдауна нет); если прежний пустой канал участника ещё не удалён, его возвращают в него, а не создают новый, не больше 15 временных каналов одновременно (иначе участника просто отключает от канала-кнопки). Настройки — константы `HUB_CHANNEL_ID`, `GAME_*`, `MAX_TEMP_GAMES` в начале `bot.py`.

## Админ-бот в Telegram (`monitoring/tgadmin.py`)

Служба `smeshariki-tgadmin` в том же Telegram-боте, что шлёт тревоги. Команды (отвечает только владельцу, чужих игнорирует): `/status` (бот, диск, память), `/logs` (последние 25 строк журнала, длинные строки скрываются), `/restart` (с подтверждением, 60 с), `/texts` (список текстов из `monitoring/texts.json`: сообщение с кнопками ролей, правила, «Как установить», шаблон баг-репорта, описание сервера; выбрать, ответить новым текстом, предпросмотр, «Применить» обновляет сообщение или описание в Discord; прежний текст сохраняется в `text_backups/<ключ>.txt` на сервере). Новый текст добавляется строкой в `texts.json` (бот может править только свои сообщения). Роль «roles» ещё и пишет `post.txt`, чтобы `bot.py post/edit` не откатил текст. Токен Discord служба берёт из `/etc/smeshariki-role-bot.env`. Работает от root, но выполняет только фиксированные действия; ввод пользователя в командную строку не попадает. Накопившееся за простой не выполняет. Ключи те же (`/etc/smeshariki-alert.env`); если `TG_CHAT_ID` — группа, нужен `TG_ADMIN_IDS`. Установка: `tgadmin.py` в `/opt/smeshariki-role-bot/`, `smeshariki-tgadmin.service` в `/etc/systemd/system/`, `systemctl enable --now smeshariki-tgadmin`.

## Ссылки-приглашения по источникам (Telegram)

`/invite <название>` создаёт бессрочную ссылку без лимита в канал `#добро-пожаловать` и запоминает метку источника (`invites.json` рядом с ботом: у Discord своих названий для приглашений нет). `/invite` без названия спросит его. `/invites` показывает все ссылки сервера с числом входов по каждой (счёт ведёт Discord), у ссылок с меткой есть кнопка удаления с подтверждением; ссылки без метки (созданные вручную) только показываются, бот их не удаляет. Одинаковые названия различаются номером. Для публикации: отдельная ссылка на Modrinth, GitHub и т. д., по числу входов видно, откуда идёт трафик.
